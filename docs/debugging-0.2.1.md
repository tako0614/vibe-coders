# 0.2.1 チャットのモデル選択とUI改善

2026-09-16。

## 変更内容

- モデルpickerを設定画面からチャット入力欄へ移動。現在のモデル名を押すと検索・一覧選択・モデルIDの直接入力ができる。矢印キーとEnterで選択し、Escapeや外側のクリックで閉じる。入力途中の検索は設定を変更せず、選択後も会話と下書きを保持する。
- 設定画面はCodex認証・APIのURL・APIキーを管理。モデルが未選択でも接続設定とキーを保存でき、モデル選択後に待機中の依頼を開始する。同じ接続先でモデルだけを変えるとキーを保持する。
- モデルは既存の仕様どおり全会話で共有。実行中は変更を止め、UIとサーバーの両方で途中の切替を防ぐ。APIキーらしい文字列をモデル名として保存する誤操作も拒否する。
- Codexの一覧は `codex debug models` を使用。ネイティブの認証・設定を使い、別のCodexセッションが会話DBを使用していても一覧を取得できる。旧CLIでコマンドが未対応の場合はApp Serverの取得を使用する。公開する情報はモデルID・表示名・既定フラグのみ。
- 白・グレー・黒を基調に、サイドバー・チャット・設定・ターミナルの色、余白、文字サイズを整理。ユーザーの発言を右側の吹き出しにし、回答のコピーを追加。
- 入力欄は内容に応じて伸び、長い入力は内部でスクロールする。日本語の変換確定では送信せず、全停止中のEnter送信も抑止する。
- 会話検索、選択中の会話の再読み込み後の復帰、スマホのサイドメニューを追加。スマホでは閉じたメニューが幅を取らず、開いている間は背景の操作を止める。Escapeとメニュー内の移動で閉じる。
- モデルpickerは入力欄の上に表示。スマホでも画面内へ収め、検索欄へフォーカスを移し、ソフトキーボードによる表示領域の変化に追従する。

## 検証

- `bun run check`：型検査、76テスト、ビルド、認証付き静的配信、元のnode_modulesを使わない配布backendの起動。
- CodexのDB初期化失敗fixtureで従来の一覧取得が失敗することを確認してから修正。カタログ取得ではApp Serverを起動せず、非表示モデルを除外する。
- モデル未選択でAPIキーを保存し、依頼がまだ推論されないことを確認。チャットでモデルを選ぶと保存済みキーを使って推論が始まる。
- このホストの実Codex CLIから6モデルを取得。0.2.0で残っていた内部SQLiteの起動失敗に依存しない経路を確認。
- ビルド済みUIを実ChromeからLANのHTTP・Basic認証で検証。モデルの検索・キーボード選択・直接入力・Escape取消・下書き保持・APIキー保持、設定からモデル欄を除去したことを確認。
- スマホのサイドメニューの検索・背景操作防止・Escape取消、pickerのフォーカスと画面内配置、入力欄の自動拡張、再読み込み後の会話復帰を確認。390px幅で横方向のはみ出しなし。
- 共通shell・デッキ・PTY・pipe・EOF・再接続、ファイル編集/差分/復元、予定、記憶、入力カード、添付と下書き、MCP設定の既存ブラウザ検証を実施。
