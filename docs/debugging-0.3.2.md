# 0.3.2: 保存済み接続先の切り替えとサイドバー

2026-09-16。

## 動作

チャットのモデルメニューにCodex・OpenRouter・OpenAI・保存済みの互換APIを表示し、選択だけで切り替えられるようにした。各接続先のモデル・effort・画像対応・キー使用設定を保持する。切り替えてもチャットの下書きは残り、以前の接続先の検索文字は次のモデル一覧へ持ち越さない。

設定画面も同じ接続先一覧を使う。APIキーの保存・差し替え・確認付き削除、互換APIの追加、保存済み設定の再利用に対応する。表示するのはキー保存済みという状態で、キーの値は返さない。Codexは引き続き端末の既存認証を利用する。

右上の作業ツールメニューを除去し、左サイドバーへ入力依頼・ターミナル・デスクトップ・予定・記憶・ファイルを移動した。モバイルではサイドバーから直接移動でき、Escapeとフォーカス復帰に対応する。

## 保存と移行

非秘密の接続先プロファイルはconfig.jsonのprovidersに保持し、使用中のproviderは既存モデル実行の境界として残す。APIキーは正規化したURL全体を対象として暗号化vaultへ保存する。使用中のprovider:mainは現在のrevisionに対する実行用参照で、接続先変更時に対象の保存済みキーから更新する。

旧設定と、CLIや専用secret入力で保存したキーは、切り替える直前に対象の保存先へ引き継ぐ。既存キーを別URLへ転送しない。モデル一覧のリダイレクトを拒否し、「APIキーを使用する」が無効の接続では保存済みキーを送らない。キー削除時には使用中のrevisionを更新し、開いていた古い入力依頼から復活しないようにする。Codexの認証ファイルはコピーしない。

## 検証

- `bun run check`に成功。96テスト、型検査、配布物ビルド、認証付きUI配信、隔離したパッケージ起動を確認。
- 接続先A/Bで別のキー・モデル・effortを保存し、Codex切り替えとストア再オープンを挟んだ復元。
- 旧設定のキー、後から専用入力で変更したキーの保持。
- 正規化URLの一致・別パス分離・未登録URL・明示的な認証省略とキー不要設定。
- キー削除後の再切り替え、古いsecret入力拒否、古い設定revision拒否、実行中の切り替え拒否。
- 設定ファイル・会話・statusレスポンス・vaultファイルにキーの平文が出ないこと。
- Chromeの隔離環境で、キーを保存したAPI接続とCodexをチャットから往復し、モデルとeffortの復元、モデル一覧の認証、下書き保持、再読み込み、モバイルのサイドバーとメニュー表示を確認。推論はfixtureを使い、実アカウントへのモデル呼び出しは行わない。
