# 0.3.1: 会話の開始、作業パネルの開閉、effortメニュー

2026-09-16。

「新しい会話」は未送信の画面を開く操作になった。最初の送信で会話とメッセージを同じトランザクションに保存し、履歴に追加する。空入力を拒否し、operationIdを下書きと一緒に保存する。応答を受信できずに再読み込み・再送しても、同じメッセージと会話を再利用する。送信中に編集された新しい入力も消さない。

送信前のシェル・接続設定には、履歴へ表示しないワークスペース用の所有コンテキストを使用する。初回送信でそのコンテキストを会話へ引き継ぐため、開いた端末やデッキは失われない。次の未送信画面は別コンテキストを使う。既存の会話・空の会話・メッセージを削除する移行は行わない。`POST /api/conversations` は空の作成ではなく、text・operationId・任意のimages/workspaceIdを受け取る初回送信APIになった。

右パネルに閉じるボタンを追加した。表示状態はHomeごと、選択画面と表示種別は会話ごとに保存する。閉じても実行中のシェル・AIは停止せず、サーバーから更新が届いても閉じた状態を保つ。チャットの「シェル」「画面」で再表示できる。

effortはモデル選択と同じ高さのボタンと、現在値のチェック・短い説明を持つメニューに変更した。矢印キー・Enter・Escape・外側クリックに対応し、小さい画面でも表示範囲に収める。モデルの対応情報、既定値、保存済み認証を維持する仕様は0.3.0と同じ。

## 検証

- `bun run check`: 型検査、92テスト、React/backendビルド、別ディレクトリでの配布パッケージ起動・認証・画面配信が成功。
- Chromeの隔離環境で、新規画面を繰り返し開いても履歴が増えないこと、最初の送信結果を意図的に失わせた後の再読み込み・再送でも会話が1件だけであることを確認。
- 下書きの文字・画像の保持、送信前のワークスペース継承、実行中シェルのパネル開閉・再読み込み後の再表示、effortの矢印キーとEnter選択・Escape・保存後の再読み込み、390px幅でのメニュー表示が成功。
- 既存の端末操作・デッキ・MCP手動設定・Codex認証フォーム・VNC操作権・2画面の独立操作・ファイル編集もブラウザ検証が成功。モデル応答は隔離fixtureを使用した。

## 常用環境への反映

0.3.1のtarballをインストールし、`http://192.168.0.122:3100` のサービスを更新した。更新直前に実行中ジョブがないことを確認し、設定・会話DB・記憶DB・vault・鍵・Atom認可ファイルの6ファイルをバックアップした。

更新前の11会話のID・タイトル・一時停止状態、91メッセージの本文、記憶DBの全行が残ることを照合した。既存の空の会話も削除していない。更新後のブラウザで新規画面を繰り返し開いても履歴数が変わらず、下書き・右パネルの閉じた状態が再読み込み後にも残ること、パネルの再表示、390px幅での表示を確認した。

確認中に接続設定がrevision 18から19へ変更され、OpenRouter・モデル未選択の状態になっていた。最新の接続設定を上書きせず、その他の設定はバックアップとの一致を確認した。Codexのnative-file認証と対応effortカタログは取得できた。常用環境ではモデル未選択のためeffortメニューは表示されず、メニューの動作確認は隔離ブラウザ環境で実施した。
