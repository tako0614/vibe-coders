# 共通shellとデッキ

0.2.0では人間と親AIが同じ実行管理を使います。Codex・Claudeを含むCLIは通常のshellコマンドとして起動します。TUI／JSONの選択を強制する専用プロンプトは追加していません。

## 画面

- 会話ごとに名前付きのデッキを作り、端末をまとめます。デッキ名、順序、所属、閉じた表示をサーバーのSQLiteへ保存します。同時編集はrevisionで照合します。
- PCでは端末をグリッド表示し、選択した端末を最大化できます。スマホでは端末セレクターで一つずつ切り替えます。
- デッキ切り替え、移動、最大化では端末を再生成しません。「表示を閉じる」は表示だけを隠し、「プロセスを停止」は実行を終了します。閉じた端末は一覧から戻せます。
- 名前変更、デッキ間移動、コピー・貼り付け、IME、特殊キー、文字サイズ保存、全画面、再接続を提供します。デッキ削除では所属端末を残るデッキへ移します。
- 「コマンドから開く」でコマンド、名前、作業フォルダ、入出力形式を指定できます。ターミナルはPTY、標準入出力はpipeで起動します。JSONの表示をTUIへ変換しません。

## 実行と入力

`POST /api/runs` のbodyは `{ conversationId, spec: { command?, mode: 'pty' | 'pipe', cwd?, title?, deckId? } }` です。人間の画面と親の `shell_exec` は同じ `RunService.start` を使います。PTYでコマンドを省略すると通常の対話shellを開きます。pipeにはコマンドが必要です。

親には `run_list`、`run_read`、`run_write`、`run_end_input`、`run_wait`、`run_stop`、`run_handoff`、PTYの `terminal_screen` と `terminal_resize` を提供します。`run_list` はデッキと実行一覧を返します。`run_wait` は最大20秒で出力またはプロセス終了を返し、長期の待機は既存の `agent_wait` と完了イベントを使います。

pipeへの入力は実行を継続したまま複数回送れます。EOFで標準入力を閉じると、それ以降の入力は拒否します。画面は入力時の改行を選択できます。出力ログはstdoutとstderrを到着順でまとめます。分離したJSON出力が必要なコマンドではshellのリダイレクトを使用できます。

PTYはブラウザなしでもDSR/DAと基本色の問い合わせに応答するため、AI単独で動かすTUIも端末応答を受け取れます。任意TUIの全拡張プロトコルを保証するものではありません。

## 境界

- プロセス終了・終了コードと、AIによる作業完了の判断は別です。JSONイベントの意味やCodexのturn、Claudeのsessionをアプリが自動解釈しません。
- 入力受付は通信への書き込み受付です。CLIが追加指示を理解したという保証はありません。到達が不明な入力を自動再送しません。
- 操作権とepochをPTY・pipeで共通に確認します。手動操作中はAIの読取と入力を停止し、人間が画面からAIへ返します。手動区間の出力をAIや永続ログへ渡さない既存の方針を維持します。
- 手動端末の終了後出力はサーバーメモリに最大32件保持し、画面から確認できます。サーバー再起動後の復元対象ではありません。AIへ返した終了済み実行からも手動区間は読めません。
- ブラウザを閉じてもプロセスは継続します。サーバー再起動時は実行をinterruptedにし、自動再実行しません。プロセス自体の独立した永続化は含みません。
- ホストのHOME、PATH、CODEX_HOME、CLAUDE_CONFIG_DIR等を使用し、cwdは作業Homeを基準とします。任意shellは同じOSユーザーの権限で動きます。

## 0.1.8からの変更

子実行専用の `NativeService`、`native_start`、`native_input`、`terminal_open`、`terminal_write` と `/api/native`、専用の起動・再開フォームを削除しました。既存native実行の保存データは履歴として読めます。HTTPの起動bodyは上記spec形式に変更し、`run_list` は `{ workspace, runs }` 形式になりました。

Codexサブスクで親を動かす `CodexModel` と、そのログイン・モデル一覧のための `CodexAuth` は独立した機能として保持しています。認証待ちから親の元の依頼が再開する契約も継続します。会話要約、Atom、MCP、共有デスクトップ、ファイル編集・復元は引き続きアプリ側が担当します。
