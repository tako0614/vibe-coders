# 0.1.6の動作修正と画面整理

2026-09-14。既存のLinux環境へログインし、HTTPのLANアドレスからChromeで操作して確認した修正です。利用者の設定・認証・会話・Atomの記憶は引き継ぎます。

## 修正内容

- **AI接続**：Codexのモデル選択とログインを一つの導線に整理。ログイン済みなら、そのアカウントを親AIへ接続できます。再起動後も認証状態を確認します。
- **作業の開始と再試行**：認証操作だけで空の会話が推論を始める問題を修正。未設定時の依頼は保持し、接続と必要なAPIキーがそろってから開始します。失敗した依頼は元のメッセージを再利用して再試行でき、無関係な実行終了で勝手に再試行しません。
- **ターミナル**：Bun PTYのセッションを分離してジョブ制御とCtrl-Cを修正。端末表示の高さが際限なく増えるサイズ調整ループを解消。手動で開いた端末にはすぐ入力でき、キー入力は順番を保って送信します。終了した端末は明示します。
- **チャット**：画面や会話を切り替えても送信前の下書きを保持。実行イベントは折りたたみ、ツールの失敗・実行中・入力待ちを区別します。過去の文章を読んでいる間はスクロール位置を保ちます。下書きはブラウザ内のメモリ保持で、ページ再読み込み後までは保存しません。
- **画面**：文字と背景のコントラストを上げ、設定をAI接続・MCP・デスクトップ・Web検索・保存と実行へ分割。子エージェント起動やイベント条件は必要なときに開く形へ整理しました。
- **読み込みと通信**：ファイルを続けて選んだときに古い応答が上書きする問題を修正。記憶とファイルに読み込み・エラー表示を追加。通信切断を表示し、復帰時に再接続します。SSEのheartbeatで無通信時の切断も検出します。

## 検証

`bun run check` で型検査、52テスト、Reactビルド、認証付き配信、配布bundleの独立起動を確認します。新しい回帰テストは `test/ui-lifecycle.test.ts` にあります。

Chromeで実際のPTYへの入力・Ctrl-C、予定の保存とコマンド実行、Atomの保存と検索、ファイル閲覧と絞り込み、MCPのstdio登録・接続・3ツールの取得、設定切替、390px幅の主要7画面を確認しました。

`bun scripts/browser-check.ts` は、隔離fixtureで認証カードの完了とコード消去、待機していたCodexの子の継続、APIキー保存、下書き保持、通信切断・復帰、遅延させたファイル選択、実VNC画面と所有権切替を検証します。モデル応答・認証成功通知にfixtureを使う部分と、実際のPTY・VNC・SQLiteを使う部分を分けています。

実アカウントのCodexログインとモデル一覧取得は成功しましたが、この検証時点の実推論は429（利用枠不足）で停止しました。画面のエラー表示と明示的な再試行は確認済みです。実モデルによる最後までの作業完了は今回の成功項目には含めません。先行版での実モデル検証は [実装状況](implementation.md) を参照してください。

既存の常用サーバーと並行してfixtureを起動する場合は、previewの `VIBE_CODER_TEST_PORT`、previewとブラウザ検証の `VIBE_CODER_TEST_ORIGIN`、Viteの `VIBE_CODER_DEV_API` と `--port` を指定できます。既定値は従来どおりAPI 3100、WebUI 5173です。
