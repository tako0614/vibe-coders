# 0.2.2: 会話と作業画面、手動MCP設定

2026-09-16。チャットと実際の作業場所を同じ画面で見られるようにし、MCP設定を手動操作中心に変更しました。

## 変更

- ロゴ、回答ごとのアバター、常設の機能メニューを除き、会話履歴・チャット・入力欄を中心に再構成。作業機能は上部の「作業ツール」から開きます。モデルpickerは入力欄に置いたままです。
- チャット横の作業画面で、同じ会話のシェルとインストール先のデスクトップを切り替えます。実際にシェル・画面を使う操作が始まると自動表示し、利用者が閉じた場合は同じ依頼中に勝手に開き直しません。スマホでは上下に並びます。
- 作業画面は既存のPTY WebSocketとVNC/画面プレビューを使用します。画面切替・閉じる操作でプロセスを終了せず、手動引き継ぎには既存の操作権管理を使います。詳細なデッキ編集は「広く開く」で使えます。
- 実行状態は入力欄の上に集約。シェルで作業中・思考中・回答作成中・入力待ち・一時停止・エラーを区別し、個々の操作や引数・結果は会話内の履歴にまとめます。結果不明の操作を完了と表示せず、中断後の古い操作も再び実行中にしません。
- MCPはローカルコマンド / HTTPの手動追加・編集フォームが基本です。認証、接続・切断、npm導入をAI未接続でも操作できます。AIへの依頼専用フォームと `/api/mcp/setup` を削除し、通常のチャット送信を使います。
- 既存のMCP設定ツールに加え、AI用の `settings_update` を追加。モデル接続・検索・保存期間・デスクトップをWebUIと共通の処理で変更します。古いrevisionは拒否し、別エンドポイントへ資格情報を引き継がず、デスクトップ設定変更で人間の操作権を奪いません。Webログイン・公開アドレス・秘密の値はこのツールの対象外です。
- 未使用のWebフォントを削除し、システムフォントへ統一しました。

## 検証

`bun run check` が通過。型検査、84テスト・495 assertions、Reactビルド、認証付きのビルド配信、作業リポジトリのnode_modulesに依存しない配布パッケージ起動を確認しました。

ブラウザ検証は隔離したHome・DBを使います。モデル状態はfixture、シェルは実PTY、デスクトップは認証付きVNCの実画面です。実アカウントで新しいAIタスクを完了した証拠とは区別します。

実Chromeの1440px / 390pxで、次を確認しました。

- 同じPTYのrun IDを保ったシェル→画面→シェルの切替、作業画面を閉じて再表示、下書き保持。
- AIの一時停止後もPTYが実行中であること。VNCプレビュー、手動操作への引き継ぎと返却。
- 実行中・思考中・回答作成中・入力待ち・一時停止・失敗・完了、操作履歴の折りたたみ。
- MCPの手動登録、4ツールのdiscovery、編集と再接続、不正なJSON引数、通信方式別の入力欄。
- 既存の端末・デッキ・ファイル編集と復元・記憶・予定・モデルpicker・Codex認証fixture・下書き・モバイルメニューを含むブラウザシナリオ一式。

今回のnpm導入画面はAI未接続でも操作可能なことを確認しました。新しいnpmパッケージを外部レジストリから導入する試験は今回再実行していません。
