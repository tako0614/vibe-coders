# 0.3.3: 記憶の構造、作業シェル、負荷時の安定性

2026-09-16。

## 共通して停止していた原因

常用DBの隔離コピーで、モデルを呼ぶ前のAtom Memory検索が`SQLiteError: Expression tree is too large (maximum depth 1000)`になることを再現した。検索語をOR式で展開していたため、長いツール出力を含む会話でSQLiteの制限に達していた。Codex・OpenRouterの双方に共通するアプリ側の経路だった。ライブラリのSQLiteアダプターを`json_each`を使う集合の検索に変更し、1600語の回帰試験で修正前の失敗と修正後の成功を確認した。

記憶取得の失敗で推論全体を止めず、その応答で参照できなかったことをチャットに表示する。モデル接続の失敗と内部処理の失敗を区別し、認証・利用枠・HTTPエラー・受信中断を表示する。

## 負荷と通信

認証情報の秘匿処理では、vaultファイルのinode・時刻・サイズが変わらない限り復号済みの秘密パターンを再利用する。別プロセスでのキー更新は次の出力時に反映する。モデルの表示テキストは増分で処理し、分割された秘密文字列を一時的にも表示しない。既に届いた全文の再処理を避けた。

接続前の待ち時間とストリーム無通信の許容時間は5分。ストリームに進捗がある間は無通信タイマーを更新する。接続中断・応答の欠落・一時的なHTTPエラーは最大2回再試行する。親の停止操作は待機中も反映する。完成したモデル応答だけをツール実行へ渡し、途中応答のツールは実行しない。ブラウザのSSEと端末の無通信判定は2分へ緩めた。ブラウザ再接続でバックエンドのシェルを作り直さない。

短い同期IOの集中とイベントループの停止を使って、シェルが生存し出力・完了を取得できることを確認した。無期限のディスク停止やOSによるプロセス終了からの継続を保証するものではない。PTYは従来どおりサーバー再起動時にinterruptedとして扱う。

## Atom Memory

Atom Memory 0.7.0の保存・検索・改訂・出典・関連・利用ackを使用する。UIには一覧、原資料、アーカイブ、本文、出典の発言、関連と逆参照、変更履歴、モデルへ渡した会話を表示する。人間による本文と関連の編集、改訂競合の拒否にも対応する。

会話の応答が完了した区切りに整理ジョブを永続化する。整理モデルへ渡した実際の発言を出典Atomとして保持し、出典の別名と関連先を検証してから記憶を作成・更新する。アシスタントの発言は未検証の主張として区別する。処理済みカーソルと計画を保持して再起動後の重複書き込みを抑止し、競合した計画は再試行時に最新の記憶から作り直す。過去の会話は記憶ページから明示的に取り込む。不要な会話から何も保存しない結果も有効とする。

UI用の索引・会話への参照は`vibe:*`メタデータで、Atom本文と改訂の正本はライブラリにある。0.7の世代依存はモデルへ渡した入力全体に保守的に結び付ける。新版のInputTokenを採用したと主張しない。

## 検証

- 1600検索語、構造を介した取得、出典・関連・改訂競合・履歴・利用記録・アーカイブ、偽の出典拒否、整理の再試行を回帰試験で確認。
- 永続シェルのcwd・export・関数、終了コード、長時間実行、同時操作拒否、同じ操作IDの抑止、手動区間の非公開と復帰、短いIO集中を確認。
- 一時障害の再試行上限、認証失敗の非再試行、キャンセル、ストリーム無通信と進捗、分割された秘密の秘匿、ツールの一度の実行を確認。
- Chromeの隔離環境で既存のチャット・接続・MCP・VNC・デッキ操作を通し、記憶の追加・編集・過去の版・モバイル詳細表示を確認。
- `VIBE_CODER_TEST_REAL_CODEX=1 VIBE_CODER_TEST_MODEL=gpt-5.6-sol bun scripts/check-memory-structure.ts`で実Codexが3件の発言から出典付き記憶2件と関連1件を生成し、再起動後の取得に成功。これは一つの統合試験で、自動整理全般の品質評価ではない。
- 元の停止会話の隔離コピーで31,582 bytesの検索コンテキストを正常に取得し、保存済みOpenRouterの`stealth/union-alpha`でも実応答を確認。常用の会話・記憶・接続設定はこの試験で変更していない。
