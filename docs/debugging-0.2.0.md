# 0.2.0 共通shell・デッキの検証

2026-09-16。[仕様と移行](shell-workspace.md)。

## 確認した範囲

- `bun run check`：型検査、74テスト、UI build、認証付き静的配信、元のnode_modulesを使わない配布backendの起動。
- 実プロセスのpipeでJSON・日本語を複数回送信し、待機・EOF・終了コードを確認。出力をCLIのturn完了へ読み替えない。
- PTYの端末問い合わせにブラウザなしで応答。全停止、操作権と古いepoch、手動区間の非公開、終了済み手動出力のAIへの非混入を確認。
- デッキ名・順序・所属・非表示の保存、古いrevisionと別会話の実行IDの拒否、非表示端末の継続実行。登録上限でプロセスだけが起動する不具合は、失敗を再現したテストを追加して修正。
- 実Chromeでログイン、並列PTY、最大化、デッキ作成・移動・並べ替え・削除、移動時のxterm非再生成、表示を閉じて戻す操作、同じshell変数の保持、手動とAIの操作権切り替え、JSON pipe入力とEOF、リロード後のデッキ復帰、390pxの単一端末表示を確認。
- 開発版に加え、ビルド済みUIをHTTPのLANアドレスからBasic認証で開き、上記操作とCodexログインカードのfixtureを検証。検証用状態は常用環境から分離。
- チャット・下書き・添付・予定・記憶・ファイル編集/差分/復元・接続設定の既存ブラウザ検証も通過。
- Codex親モデルの認証待ち・元の依頼の再開・キャンセル・課金先非切り替えはfixtureで回帰確認。子実行専用のnativeテストは共通shellの実プロセステストへ置き換えた。
- Codex・API共通のモデルpickerを追加。モデル未設定で一覧を取得し、検索・選択・直接入力を行える。APIキーの一時利用、保存済みキーを使うモデル変更、別URLへのキー非転送、redirect拒否、認証情報の画面・履歴非混入をテスト。
- LANの実Chromeで、Codexモデルの直接入力と一覧選択、APIモデルの検索・選択・直接入力、キーの保存、モデルだけ変更した後もキーが維持される流れを確認。
- このホストの既存Codex認証を使い、新規ログイン要求0件で認証を確認。実Codexから6モデル、OpenRouterの公開APIから443モデルを取得した（件数は検証時点）。Codex App Serverは明示的なstdio接続を使用する。
- Windowsの配布チェックは一時ファイル削除時のEBUSYを再現し、deferred handle解放と上限付き再試行で修正。shell実装とこの修正を含む `433e756` はLinuxのテスト・Docker build、macOS/Windowsの配布build・起動チェックを通過。

## 制限

この版の共通shellから実アカウントのCodex/Claudeに推論させる総合試験は未実施。0.1.8時点の利用枠・認証の失敗を、この版の成功実績として扱わない。Linuxで検証し、macOS/Windowsの実機検証は未実施。

サーバー再起動でPTY自体は復活しない。管理状態・デッキ・永続ログを復元し、消えたプロセスはinterruptedとする。手動区間の出力は永続ログに保存せず、サーバーメモリ内に限って表示する。

npm認証は `npm whoami` が401を返したため公開待ち。公開済み版は0.1.8。

0.2.0のtarballを作成し、別ディレクトリへのnpmインストールとCLI起動を確認。常用環境の設定・会話DB・Atom DBはバックアップし、SQLiteの整合性を確認した。常用3100番は0.1.8のまま。動いている端末3つを終了させる必要があるため、0.2.0への再起動は確認待ち。
