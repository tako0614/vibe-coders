### Codexを親の接続先として有効化

初回の反映では既存のOpenRouter設定を保持していたため、Codexの保存済み認証を読めても、親の接続先はCodexになっていなかった。認証確認だけでは実際のチャット接続を確認したことにならない。

利用者から未接続の指摘を受け、設定をバックアップしたうえで、常用版の接続先をCodexへ変更した。モデルは端末のCodex設定と同じ `gpt-6-astra`。新規の検証会話へ短い接続テストを送信し、実サブスクの親から `CODEX_CONNECTION_OK` の返答とidleへの復帰を確認した。追加のログイン要求やツール呼出しは発生していない。

実Chromeでも返答・モデル名・接続済み表示・既存認証の利用を確認した。設定変更だけで反映され、サービスの再起動は不要だった。モデル一覧を取得するApp ServerのDB初期化失敗は以下の制限として残るが、親のResponses接続と実応答は成功している。

## 制限

この版の共通shellから実アカウントのCodex/Claudeに推論させる総合試験は未実施。0.1.8時点の利用枠・認証の失敗を、この版の成功実績として扱わない。Linuxで検証し、macOS/Windowsの実機検証は未実施。

サーバー再起動でPTY自体は復活しない。管理状態・デッキ・永続ログを復元し、消えたプロセスはinterruptedとする。手動区間の出力は永続ログに保存せず、サーバーメモリ内に限って表示する。

npm認証は `npm whoami` が401を返したため公開待ち。公開済み版は0.1.8。

常用環境のCodexモデル一覧は取得できていない。反映前の単体確認では6モデルを取得できたが、反映後は同じホストのCodex CLI単体でも内部SQLiteの初期化に失敗した。書込みロック競合と `state db backfill ... status: running` を確認。ほかのCodex作業を停止したり、CodexのDBや認証保存先を変更する対応は行っていない。一覧の取得失敗はUIへ表示され、モデル名の直接入力と保存済み認証の利用は確認済み。

この一覧取得の不具合は [0.2.1](debugging-0.2.1.md) で修正。旧版の記録として、上記には0.2.0での結果を残す。
