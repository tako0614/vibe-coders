# 0.1.7: 端末の遅延と自動デスクトップ

2026-09-14。Linuxのインストール先で実機検証。

## 端末

以前は出力を350msごとに取得し、キー入力ごとにHTTPリクエストを送っていました。さらに秘密の長さに合わせて出力の末尾を常に保留していたため、長い認証情報があると短い入力やプロンプトが表示されませんでした。

入出力をWebSocketへ変更しました。所有者・実行・操作権の版に結びついた一回限りの接続券を使い、操作権の変更と全停止で接続を失効させます。画面の描画完了に合わせて出力を確認し、遅いクライアントのバッファを制限します。切断後は差分を取得し、到達したか不明な入力は再送しません。

AI向けの出力は秘密と一致する可能性のある末尾だけを保留します。人間の操作区間はログとAIの端末画面に保存せず、認証済み本人へのライブ表示だけに使います。手動操作から返却するとAI側の画面も消去します。

横並びの端末タブ、終了履歴の切替、コピー・貼り付け、文字サイズ、全画面、再接続、スマホ向けのEsc・Tab・Ctrl+C・矢印キーを備えます。

実Chromeから同じホストのLAN URLへ12回入力した測定では、入力イベントから端末の描画まで中央値9.8ms、最大17.2msでした。旧0.1.6の実アカウントでは最初の短い入力が表示されず、測定がタイムアウトしました。公開版をインストールしたLANの本番環境でも12回測定し、中央値7.7ms、最大14.1msでした。別端末や異なるネットワークで同じ遅延を保証する値ではありません。

## インストール先のデスクトップ

手動VNC設定がある場合はその設定を使います。未設定のLinuxでは、起動時に現在のDISPLAY、またはアクセス可能な`:0`・`:1`を確認します。他ユーザーのXauthorityを取得しません。画面がない場合は、そのHome専用のXvfb、Openbox、端末、認証付きVNCを起動します。

Debian / Ubuntuは不足パッケージをrootまたはパスワード不要のsudoで導入します。権限不足などの場合は必要なコマンドと再試行操作を画面に出します。npm install自体ではOSのパッケージを変更しません。Chrome・Chromiumはインストール済みの実行ファイルを専用プロファイルで起動します。ブラウザがない場合はインストールが必要です。

自動起動したX11には認証cookieを設け、VNCはloopbackだけで待ち受けます。認証情報・PIDと起動時刻はHomeごとの状態領域に保存します。通常終了と異常終了後の再起動で、自身が起動したプロセスだけを回収します。

AI操作中も画面をプレビューできます。これはAIの観測IDを消費しない読み取り専用の画像取得です。手動操作へ切り替えると同じ画面をnoVNCで操作でき、AIの画面取得と入力を停止します。AI用の`desktop_launch`も同じ操作権を守ります。

## 検証

- `bun run check`: 57テスト、型検査、Reactビルド、別ディレクトリの配布bundle起動・認証・migration・画面配信。
- 実WebSocketで一回限りの券、Origin・実行ID・版の照合、即時入力、切断中の出力取得、操作権変更での失効。
- 実Xvfb/VNCで設定なしの起動、画像取得、入力、プレビューとAI観測の独立、認証cookieなしの接続拒否。
- 親プロセスを強制終了してから再起動し、記録したGUIプロセスを回収。既存X11画面を再利用し、切断時に元の画面を停止しないことも確認。
- 実Chromeの14項目: ログイン、チャット、端末入出力・貼り付け・文字サイズ・再接続・スマホ幅、下書き、通信復帰、ファイル選択、予定、記憶、接続設定、Codexログインfixture、実noVNCと操作権の返却。
- LANの隔離環境で自動デスクトップ、Chrome起動、AI操作中のプレビュー、1280×800の手動操作画面。

macOS・Windows・通常のWayland画面の直接自動接続は未対応です。手動VNCの経路を使用します。Dockerfileには自動デスクトップの依存を追加していますが、この環境でのDocker実起動は未検証です。実Codexサブスクの推論は前回の利用枠エラーから今回再試行しておらず、今回の改善を実モデルの完走実績とはしていません。

公開npm tarballのSHA-512一致、公開registryからのインストール、CLIとHome初期化を確認し、LANで稼働中の0.1.6を0.1.7へ更新しました。設定・会話・Codex認証を保持し、デスクトップの手動設定なしで専用画面が起動しています。
